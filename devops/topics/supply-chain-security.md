# Deep Dive: Supply Chain & Artifact Security — SBOM, Signing, SLSA, Policy

> **Standalone deep dive:** Attack surface extends beyond your code: base images, dependencies, CI runners, registries. Provenance + signing + policy earn your artifacts a verifiable identity.

---

## 1. The Attack Chain & Real Campaigns

```
Source repo → Dependencies (lock) → CI build env → Container registry → Admission → Runtime
   ↑ SolarWinds      ↑ log4j/typo-squat  ↑ 3CX build-compromised  ↑ GitPoll/registry
   ↑ every repos   ↑ scoped-gha GH dirty  (pinned deps)             ^ pull whatever
```
**Modern posture: treat unknown as hostile.** Only artifacts with:
```
KNOWN source (repo+commit in provenance) + KNOWN build (CI identity + hermetic) 
+ SCANNED + SIGNED (identity claim) → allowed to run
```

## 2. SBOM — The Inventory

| Field | Content |
|-------|---------|
| Format | SPDX (or CycloneDX) |
| Contents | packages (name, version, licenses, hashes), relationships |
| Generators | syft, trivy, cyclonedx-tool, cdxgen |

```bash
syft myapp:1.0 -o spdx-json > sbom.spdx.json
trivy image --format cyclonedx > sbom.cdx.json
# keep SBOM with artifact or as attestation; regenerate/verify on rebuild
```
**Value:** vulnerability triage in minutes (know exactly which package affected), license compliance, provenance from you to consumers.

## 3. Signing — cosign (Sigstore)

```
Keyless (OIDC, recommended):
  CI (GitHub/ADo) gets an OIDC token proving workflow+repo+ref
  cosign signs using ephemeral cert issued via Fulcio — no key to store/leak
  Verification: cert chained to trusted root + identity assertion
Key pair (existing stacks):
  pub_sign.pem published (verify anyone); private key in KMS/HV store only
```
```bash
# keyless sign + verify
cosign sign ghcr.io/myorg/myapp:1.0
cosign verify ghcr.io/myorg/myapp:1.0 \
  --certificate-identity "https://github.com/myorg/.github/.github/workflows/ci.yml@refs/heads/main" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com"
# attestations (SBOM as signed evidence)
cosign attest --predicate sbom.spdx.json --type spdx ghcr.io/myorg/myapp:1.0
cosign verify-attestation --type spdx ghcr.io/myorg/myapp:1.0
```

## 4. SLSA — Levels of Trust

```
L0: no provenance
L1: provenance available (who built what) — signed? maybe
L2: + signed provenance (build identity)
L3: + non-forgeable provenance (source+build ID tied), canonical build 
L4: + hermetic, reproducible, isolated build env — max trust
```
**Attainable goal = L3:** signed provenance generated by CI (OIDC), attest via `slsa-github-generator` official action. L4 niche.

---

## 5. CI Build Hardening (the trust anchor)

```
- GitHub Actions: pin every action to commit SHA (dependabot keeps current) — no tags
- Use official/high-trust actions; review third-party supply chain (rare)
- OIDC for cloud auth (no static secrets in runner); least privilege scoped
- New-lineage: build from source tag only, immutable inputs
- Cache poisoning guard: pin base images by digest
- Hermetic-ish: reproducible builds (same commit → same image) enable MarineCorp-style verification
```

## 6. Enforcement — Admission + Registry Policy

```yaml
# Kyverno ClusterPolicy: only signed + allowlisted images
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata: { name: verify-images }
spec:
  validationFailureAction: Enforce
  rules:
    - name: allow-signed
      match: { resources: { kinds: [Pod] } }
      verifyImages:
        - imageReferences: ["ghcr.io/your-org/*"]
          attestors:
            - count: 1
              entries:
                - keyless:
                    subject: "https://github.com/your-org/*/.github/workflows/ci.yml"
```
- **Registry**: scan-on-push (ACR/Defender, GHCR trivy), quarantine policy (block vulnerable pull)
- **Admission**: Kyverno `verifyImages` + allowlist registry + require SBOM annotation (optional via `image-references`)
- **Runtime**: Trivy-operator continuous reports + Falco drift (unexpected exec) — baseline deviation alert

## 7. Real World Checklist (reproduce in your repo)

```
[ ] Actions pinned to SHA; dependabot auto-updates
[ ] OIDC for cloud/registry auth (zero static secrets)
[ ] Base image: distroless/nonroot, pinned by digest
[ ] Every build: scan (trivy) + SBOM (syft) + sign (cosign keyless)
[ ] Registry scan-on-push + allowlisting
[ ] Admission verifies signature + allowlist + (optional) SBOM
[ ] Provenance (SLSA L3) via official SLSA generator
[ ] Runtime continuous scan + drift monitor + alerting
```

## 8. Interview Questions — Supply Chain

| Question | Strong answer |
|----------|---------------|
| "SBOM kya use?" | Inventory+pkg-version+license; triage logical4j in minutes; compliance; evidence for consumers. Generators: syft/trivy. |
| "Cosign?" | Sign/verify container: keyless (OIDC certs, no secrets) or key-pair in KMS; attest (attach SBOM/provenance) as signed predicate. |
| "SLSA L3?" | Signed, non-forgeable provenance (source+build identity) via official generators; L4 hermetic. |
| "Threat model / why chain?" | Attacks at source/deps/build/registry/admission; any link uncontrolled = risk. Policy each link. |
| "Enforce admission?" | Kyverno verifyImages: signature + allowlist; reject unknown/unsigned at pod creation. |
| "Pinned actions kyu?" | Supply chain at CI: untagged action could change → build compromised; SHA pin + review. |
| "Attack surface of base image?" | Reproducible distroless+SHA, scan gate, sign — smaller surface, faster triage. |
| "Registry policy?" | private/allowlist only, scan-on-push block vulnerable, pull-by-digest (avoid mutable latest). |
